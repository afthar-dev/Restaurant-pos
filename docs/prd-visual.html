State machines

How each record moves

Order

PENDING_APPROVAL→OPEN→BILLED→CLOSED

Pending only for QR orders. Any order not yet closed can become CANCELLED.

KOT on the kitchen screen

NEW→PREPARING→READY→SERVED

READY pings the waiter's phone. A cancelled item sends a separate CANCEL KOT.

Bill

OPEN→PAID·VOID

Void needs a manager and a reason. The bill number is kept and never reused.

Table

VACANT→RUNNING→BILL_PRINTED→VACANT

The table's QR token rotates each time it goes vacant.

Order item

NEW→SENT·CANCELLED

Cancelling a sent item needs manager permission and is audited.

Business day

OPEN→CLOSED

No open day means no ordering. Only the owner can reopen a closed day.

Key journeys

Service flows

Dine-in

  1. Waiter taps a table; an open order starts and the table turns running.
  2. Adds items with variant, add-ons and notes.
  3. Send KOT: items split by station, shown on the kitchen screen and printed.
  4. More items later go out on a new KOT with only the new items.
  5. Kitchen marks ready; the waiter's phone gets a ping.
  6. Print bill, record payment, table goes vacant.

Parcel

  1. Cashier starts a parcel order and a token number is assigned.
  2. Items use parcel price plus packaging charge.
  3. Send KOT, print bill, take payment (pay first by default).
  4. When the kitchen marks ready, the token shows in the pickup list.

QR order with approval

  1. Customer scans the signed table QR and sees the live menu.
  2. Submits; the order waits as pending approval.
  3. Captain app and POS get an alert.
  4. Staff review, edit if needed, then approve to fire the KOT.
  5. On reject, the customer sees “please call the waiter”.

Day close

  1. Manager opens the day with the opening cash amount.
  2. All orders, payments and expenses are tagged to that day.
  3. Close is blocked while any order or bill is unpaid.
  4. Expected cash = opening + cash sales − cash expenses.
  5. Manager counts cash; the variance is stored and the report prints.

Calculation order

line_total   = (price + add-ons) × qty − item discount
subtotal     = Σ line_total
taxable      = subtotal − bill discount + packaging
line_taxable = line share of taxable (pro-rata)
cgst, sgst   = Σ line_taxable × rate ÷ 10000
total        = taxable + cgst + sgst → nearest ₹
round_off    = rounded total − exact total
  • Money is stored as whole paise; rates as basis points (2.5% = 250).
  • Composition scheme prints “Bill of Supply” with no tax lines.
  • Each order item stores its name, price and tax when it was added, so menu edits never change old bills.
  • Bills are never deleted. Bill, KOT and token numbers are gap-free per financial year (April to March).

After launch
Client advisory: keep a 4G backup router at the counter

The system is cloud-hosted, so billing needs internet. Offline mode is out of scope. Every screen shows a clear banner when the connection drops, and print jobs queue with a Reprint button.
