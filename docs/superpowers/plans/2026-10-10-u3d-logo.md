# U3d Restaurant Logo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Owners upload a restaurant logo in Admin → Settings; it shows in the staff header, on printed bills and in the customer QR menu header.

**Architecture:** A `MediaService` in `apps/api/src/media` owns "store a new image, point a row at it, drop the old one" with the R2-safe ordering dish photos already use; dish photos and the logo both use it. `Outlet.logoId` points at a `Media` row. Views add `logoUrl` (outlet settings, QR session, bill print payload). The web reuses `shrinkPhoto` with a 512 px limit.

**Tech Stack:** NestJS 11 + Prisma 6 (API), React 19 (web, QR), Vitest/Jest.

**Spec:** `docs/superpowers/specs/2026-10-08-u3d-logo-design.md`. Update: the QR header's saffron icon square shows the logo instead when one is set.

## Global Constraints

- Same limits and errors as dish photos: 1 MB, JPEG/PNG/WebP by magic bytes, `FILE_TOO_LARGE` 413, "Use a JPEG, PNG or WebP photo." 400.
- `settings.manage` for upload/remove; audit `outlet.logo`.
- R2-safe order: object first, rows in a transaction, remove the new object if rows fail, remove the old object after commit.
- No logo → every screen looks exactly as today.
- Migration hand-written; live DB diff empty after it.

## Review Focus

- **Replacing a logo twice quickly:** no orphaned media rows or files.
- **Local storage URLs on printed bills:** relative `/api/media/…` made absolute for the print iframe.
- **Transparent PNG logo:** stays transparent (WebP) and readable on dark headers.
- **Dish photos unchanged** after the `MediaService` refactor (existing e2e stay green).

## Tasks

### Task 1: MediaService and dish photos on it
`MediaService.replace({ outletId, bytes, link(tx, mediaId), old })` validates, puts the object, runs one transaction (create media row, `link`, delete old row), discards the new key on failure and the old key after commit; `MediaService.remove({ old, unlink(tx) })`; `urlFor(key)`; `discard(key)` logs, never throws. Unit tests: new object removed when the transaction fails; `discard` swallows storage errors. `MenuService` photo methods use it; dish-photo e2e stay green. Commit.

### Task 2: Outlet logo API
Migration `outlet.logo_id` (nullable, FK to media, `ON DELETE SET NULL`); `PUT /api/outlet/logo` (multipart `image`) and `DELETE /api/outlet/logo`; `logoUrl` in `GET /api/outlet`, QR session start `outlet`, bill print payload `outlet`. E2E: set, replace (old file gone, one media row), remove, view fields, cashier 403, wrong type 400, too big 413. Commit.

### Task 3: Staff app
`shrinkPhoto(file, maxSide = 1024)`; Settings **Logo** section (preview, Add/Change/Remove, uploads on pick, toast "Logo saved"); header logo before the outlet name (28 px, `object-contain`); bill template logo (`max-height:18mm; max-width:60%; filter:grayscale(1)`, absolute URL, escaped). Tests for each. Commit.

### Task 4: QR header
Session type `outlet.logoUrl`; header shows the logo in the 48 px square (`object-contain`, `alt=""`) instead of the icon when set. Tests: logo shown when set, icon otherwise. Commit.

### Task 5: Browser, review, merge
Upload a real logo, see header (light/dark), print a bill preview (stubbed print), QR header. Full checks, fresh review, fixes with tests, merge.
